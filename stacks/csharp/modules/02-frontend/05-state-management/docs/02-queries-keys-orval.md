# Queries, keys, and generated hooks with Orval
[← Overview](00-overview.md)

## Why it matters
- Hand-written `fetch` calls disagree with the C# DTOs: the API renamed `priceMinor` to `unitPriceMinor`, nothing failed at build time, and product cards showed `NaN`.
- Two components use different query keys for the same data (`["order", id]` and `["orders", id]`); invalidation updates one and not the other.
- `staleTime` is left at 0; every tab switch and focus refetches the whole catalog.

## Concepts

### useQuery essentials
```tsx
const { data, isPending, isError, error, isFetching } = useQuery({
  queryKey: ["orders", orderId],
  queryFn: ({ signal }) => apiFetch<OrderDto>(`/orders/${orderId}`, { signal }),
  staleTime: 30_000,
});
```
| Option / state | Meaning |
|:--|:--|
| ⭐ `queryKey` | cache identity; an array that includes every input (`["products", filters]`) |
| `queryFn({ signal })` | fetches; pass `signal` so superseded requests are aborted |
| ⭐ `staleTime` (default 0) | how long data counts as fresh: no refetch while fresh |
| ⭐ `gcTime` (default 5 min) | how long **unused** data stays in memory |
| `enabled` | don't run until ready (dependent queries) |
| `select` | derive/transform data for this component |
| `placeholderData` | show something while the real data loads (`keepPreviousData` for pagination) |
| `isPending` | no data yet |
| `isFetching` | any fetch in flight (including background refetch) |

`staleTime` ≠ `gcTime`: stale data is still shown, then refreshed in the background; garbage-collected data is gone.

### Query keys
- Hierarchical: `["products"]` ⊃ `["products", "list", filters]` ⊃ `["products", "detail", id]`. Invalidating `["products"]` hits all of them.
- Include every variable the query depends on; keys are hashed deterministically (object key order doesn't matter).
- Centralize keys in factories (or let Orval generate them).

### queryOptions and prefetching
```ts
export const productQuery = (slug: string) => queryOptions({
  queryKey: ["products", "detail", slug],
  queryFn: ({ signal }) => apiFetch<ProductDto>(`/products/${slug}`, { signal }),
  staleTime: 5 * 60_000,
});
// reuse: useQuery(productQuery(slug)); queryClient.prefetchQuery(productQuery(slug)); queryClient.getQueryData(productQuery(slug).queryKey)
```
Prefetch on hover/focus of a link (`onMouseEnter={() => queryClient.prefetchQuery(productQuery(slug))}`), or on the server in Next.js and hydrate (06-rendering).

### Dependent and parallel queries
- Parallel: several `useQuery` calls, or `useQueries({ queries: ids.map(id => orderQuery(id)) })`.
- Dependent: `enabled: !!customerId` on the second query.

### Orval: hooks from the OpenAPI contract
Orval reads `openapi/shop-api.json` (generated by ASP.NET Core at build time) and writes typed functions, TanStack Query hooks, query key helpers, and optionally Zod schemas and MSW mocks.

| Generated (operationId `GetOrder`) | Use |
|:--|:--|
| `getOrder(id, options)` | plain function calling your fetcher |
| `useGetOrder(id, { query: { staleTime } })` | query hook |
| `getGetOrderQueryKey(id)` | key for invalidation and `setQueryData` |
| `getGetOrderQueryOptions(id)` | options for prefetching and `useQueries` |
| `useCreateOrder()` (operationId `CreateOrder`) | mutation hook |
| `OrderDto`, `CreateOrderRequest` | TypeScript types from C# DTOs |

Rules: generated files are never edited by hand; regenerate in the PR that changes the API and diff them in CI (01-foundations/08-documentation). Wrap generated hooks in a feature hook only when you need shared options or data shaping.

## Example
`web/orval.config.ts`
```ts
import { defineConfig } from "orval";

export default defineConfig({
  shop: {
    input: { target: "../openapi/shop-api.json" },
    output: {
      mode: "tags-split",
      target: "src/api/generated/shop.ts",
      schemas: "src/api/generated/model",
      client: "react-query",
      httpClient: "fetch",
      override: {
        mutator: { path: "src/api/fetcher.ts", name: "apiFetch" },   // credentials, timeouts, Problem Details → ApiError
        query: { useQuery: true, useSuspenseQuery: true },
      },
    },
  },
  shopZod: {
    input: { target: "../openapi/shop-api.json" },
    output: { mode: "tags-split", client: "zod", target: "src/api/generated/zod" },
  },
});
```
`web/package.json` scripts: `"api:gen": "orval"`.

`web/src/features/orders/OrderDetails.tsx`
```tsx
"use client";
import { useGetOrder, useGetOrderShipments } from "@/api/generated/orders/orders";

export function OrderDetails({ orderId }: { orderId: number }) {
  const order = useGetOrder(orderId, { query: { staleTime: 30_000 } });
  const shipments = useGetOrderShipments(orderId, { query: { enabled: order.data?.status === "Shipped" } });

  if (order.isPending) return <p>Loading order…</p>;
  if (order.isError) return <p role="alert">Couldn't load the order.</p>;

  return (
    <section>
      <h1>Order #{order.data.id}</h1>
      <p>Status: {order.data.status}</p>
      {shipments.data?.map((s) => <p key={s.trackingNumber}>{s.carrier}: {s.trackingNumber}</p>)}
    </section>
  );
}
```
The exact response shape of generated fetch functions (raw data vs `{ data, status, headers }`) depends on Orval's `httpClient` and mutator settings; check the generated types once and keep the mutator returning plain data.

## Production patterns
- Set sensible defaults once on the `QueryClient` (`staleTime: 30_000` for most API data), override per query.
- Keys mirror API resources; generated key helpers are the only way code builds keys for API data.
- Regenerate the client in the same PR as the API change; CI fails if generated files are stale.
- Prefetch on intent (hover, focus) for detail pages; never prefetch everything.

## Mistakes
Wrong: keys missing inputs.
```ts
useQuery({ queryKey: ["products"], queryFn: () => getProducts(filters) });   // all filters share one cache entry
```
Right: `queryKey: ["products", "list", filters]` (or the generated key helper).

Wrong: editing generated files to "fix" a type.
Right: fix the C# DTO or OpenAPI metadata, regenerate.

## Check yourself
1. What is the difference between `staleTime` and `gcTime`?
2. Why must the `queryKey` contain every variable the `queryFn` uses?
3. Where do generated TypeScript types come from in this stack?

<details><summary>Answers</summary>

1. `staleTime`: how long data is fresh (no refetch). `gcTime`: how long unused data stays in memory before removal.
2. The key is the cache identity; a missing variable makes different requests share and overwrite one cache entry.
3. From the ASP.NET Core API's OpenAPI document, generated at build time, run through Orval.
</details>
