# Practice cheatsheet
[← Module](README.md) · The most-used rows from each topic cheatsheet. Follow a heading for the full sheet.

## [01 · Engineering Practice](01-engineering-practice/docs/cheatsheet.md)
| Item | What it does |
|:--|:--|
| Vertical slices, PRs under ~400 lines | fast, deep reviews |
| Flags for unfinished work | merge daily, release later |
| Acceptance criteria (given / when / then) | everyone builds the same thing |
| Range estimates with confidence | honest plans |
| Review within one working day | short waits |
| Correctness → security → design → operability → tests | review priorities |
| Conventional Comments (`issue (blocking):`, `nitpick (non-blocking):`) | clear expectations |
| Self-review + PR description (what, why, how to test, risks) | easier reviews |
| Debt issues with cost and trigger | debt that gets prioritized |
| Short design doc with alternatives, shared early | fewer wasted weeks |
| Bottom line up front, escalate the same day | no surprise delays |
| `git bisect run <test>` | find the breaking commit |
| Review AI code strictly, verify APIs, add tests | safe AI assistance |
| Done = working in production, watched after deploy | real ownership |
